## 背景图片 picker 弹窗「下方两个按钮不显示」修复（BackgroundPicker.kt）

### 症状
`BackgroundPickerPreference`（设置背景 / 动态背景）弹窗里，底部的「恢复默认 / 保存」
两个按钮在内容较高（开启模糊 + 亮度滑块、或小屏）时不显示、点不到。

### 根因（两个，独立）
1. **弹窗高度不受限**：核对 Miuix 0.9.4 源码 `commonMain/top/yukonga/miuix/kmp/layout/DialogContentLayout.kt`
   —— 手机（非大屏）走底部对齐分支，`contentModifier.heightIn(max = Dp.Unspecified)`，
   弹窗高度完全由内容决定；只有大屏才有 `windowHeight * 2/3` 上限。
2. **Compose Column 会「吃掉」末尾子项**：Column 给每个非 weight 子项传的是
   `maxHeight = 剩余高度`，内容一旦超出可用高度，**最后的按钮行被压成 0 高度 → 不可见**。
   （这是与 Android LinearLayout 的关键差异：不是溢出裁切，而是末尾子项被压扁。）
3. 附带发现：`BackgroundPreview` 的 `.width(200.dp).heightIn(max = X).aspectRatio(0.72f)`
   里 `heightIn` **形同虚设**——核对 Compose `foundation-layout` 的 `AspectRatio.kt`
   `Constraints.findSize()`：宽度被固定成 200、比例推出的 277.8dp 高度超过 maxHeight 时，
   前四步 `enforceConstraints=true` 全部失败，第五步 `tryMaxWidth(enforceConstraints=false)`
   直接返回 200×277.8，**违反传入的 maxHeight**。所以预览恒为 277.8dp 高，是撑爆弹窗的主因。

### 修法（BackgroundPicker.kt 单文件，两处弹窗都改）
- `BackgroundPreview`：改为**高度驱动**——
  `val previewHeight = (screenHeightDp.dp * 0.34f).coerceIn(150.dp, 260.dp)`，
  Modifier 改为 `.height(previewHeight).aspectRatio(0.72f, matchHeightConstraintsFirst = true)`，
  宽度由 0.72 反推（约 0.72×H），尺寸完全确定、不再有约束冲突。
- 两个弹窗的 content Column 内层再包一层
  `Column(Modifier.fillMaxWidth().weight(1f, fill = false).verticalScroll(rememberScrollState()), CenterHorizontally)`，
  预览 + 说明 + 滑块全部挪进这一层；**按钮 Row 留在外层**。
  原理：weight 子项在非 weight 子项之后测量，按钮先拿到自己需要的高度，剩余空间才给滚动区
  → 按钮永不消失，弹窗总高也不会超过可用高度（标题不再顶出屏幕）。
- 清理 import：删掉已不再使用的 `layout.heightIn` / `layout.width`，
  新增 `rememberScrollState` / `verticalScroll`（本轮分 4 次串行 Edit，首次 Edit 后先用 grep
  核对 `width`/`heightIn` 是否还有使用点，再删 import）。

### 复用结论（下次写 Miuix 弹窗先看这三条）
- Miuix `WindowDialog` 在手机上**不限制高度**：内容必须自己滚动，否则末尾元素被压扁/溢出。
- 项目既有正确范式：`SettingsCardColors.CardColorPreference` 与 `UpdateAvailableDialog`
  都是「外层 Column + 内层 `heightIn(max) + verticalScroll` + 按钮在外层」。
- Compose `Column` ≠ LinearLayout：非 weight 子项拿到的是**剩余高度**，末尾子项会被压到 0。
  想让某个区域吸收溢出，用 `weight(1f, fill = false)` 而不是 `heightIn`。
- `Modifier.width(x) + heightIn(max) + aspectRatio(r)` 这个组合**不可靠**；
  要固定尺寸就只固定一条边，另一条交给 `aspectRatio(r, matchHeightConstraintsFirst = true)`。

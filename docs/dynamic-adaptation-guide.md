# 动态适配使用指南

> 适用于 HyperBackground 1.4.4-beta11 及后续包含「动态适配」页面的版本。

「动态适配」用于把 HyperBackground 的卡片材质、弹窗、搜索框、顶栏元素以及全局壁纸等能力，按**组件类型**和**应用**分别控制。它和传统的“为某个页面写死一条适配规则”不同：模块会在运行时识别符合条件的界面组件，再根据你的作用域设置决定是否接管。

## 使用前准备

1. 安装并在 LSPosed 中启用 HyperBackground。
2. 在 LSPosed 的模块作用域中勾选希望 HyperBackground 生效的应用。
3. 修改作用域后，建议结束目标应用进程并重新打开；部分系统应用可能需要重启设备。
4. 打开 HyperBG，切换到底部的「动态适配」。

> 「软件作用域」读取的是 LSPosed 中当前实际启用的作用域。若页面提示模块未激活或列表为空，请先检查 LSPosed 是否启用了模块及对应应用。

## 一、先设置卡片背景样式

动态适配页面顶部的「设置分组卡片」决定卡片类组件使用什么材质。

可根据当前版本提供的选项选择系统默认、自定义颜色、磨砂或柔光玻璃，并分别配置浅色/深色效果。柔光玻璃还可以进入「柔光参数」继续调整模糊、光影、折射、背景等参数。

beta11 支持卡片配置的导出、导入和统一恢复默认。导入卡片配置只覆盖卡片模式、明暗配色、模糊及柔光参数，不会覆盖其它背景与外观设置。

### 材质回退

柔光玻璃依赖系统原生材质与背景模糊能力。目标设备或目标界面不满足条件时，模块会按可用能力回退，避免因为材质接口不可用直接留下异常透明面。

## 二、顶栏效果

「模糊」区域用于控制支持页面的顶栏表现：

- **顶栏模糊**：开启后可调节模糊强度和不透明度。
- **顶栏透明**：让顶栏保持透明，与顶栏模糊互斥。

如果你希望背景从页面内容连续延伸到顶部，可尝试顶栏透明；如果希望文字区域和背景之间有更明显的层次，则更适合使用顶栏模糊。

## 三、组件作用域

进入「组件作用域」后，可以决定**哪一类界面元素允许被动态适配**。这里是全局总开关。

当前可控制的组件包括：

| 组件 | 作用 |
| --- | --- |
| 分组卡片 | 设置、安全中心等页面中由 RecyclerView 分组装饰器绘制的卡片 |
| 独立卡片 | 自带圆角卡面的独立 View，例如省电与电池中的部分卡片 |
| 弹窗 | 右上角菜单、下拉选择框等 MIUIX PopupWindow / PopupView 类弹窗 |
| 悬浮操作底栏 | 应用详情等页面的 MIUIX 悬浮操作菜单，不影响普通底部导航栏 |
| 搜索框 | 支持页面的搜索框材质，例如设置主页搜索框 |
| 顶栏按钮 | 用自定义材质参数覆盖支持页面顶栏按钮的背景与折射 |
| 全局壁纸 | 把「全局设置」中配置的背景图应用到作用域应用的大页面 |
| 布局清理 | 扫描并清理遮挡全局背景的页面色块 |

### 顶栏按钮常驻背景

开启「顶栏按钮」后，会出现额外的「顶栏按钮背景」选项。关闭顶栏按钮组件时，这个附属选项也会一并关闭。

### 全局壁纸

「全局壁纸」不会凭空生成背景。请先在 HyperBG 的「全局设置」中配置壁纸；未配置时，页面会提示“请先到全局设置配置壁纸”。

### 布局清理

当全局壁纸已经注入，但页面仍被大块纯色背景遮住时，可以尝试开启「布局清理」。它用于清理覆盖在背景之上的页面色块，而不是替代卡片材质。

## 四、软件作用域

「软件作用域」用于决定**哪些 LSPosed 作用域应用实际使用动态适配**。

页面会从 LSPosed service 读取当前 HyperBackground 已启用的包名，并显示应用名称、包名和图标。

每一行有两种操作：

- 点击右侧开关：直接启用或关闭这个应用的整包动态适配。
- 点击应用这一行：进入该应用的详细组件设置。

因此，如果你只想让某几个系统应用使用新材质，不需要退出 HyperBG 去反复修改全局组件开关，可以直接在这里按应用控制。

## 五、为单个应用单独配置组件

进入某个应用后，可以进一步决定它允许使用哪些组件。

这里**只显示「组件作用域」中已经全局开启的组件**。例如全局关闭了「弹窗」，那么某个应用的详情页里不会出现「弹窗」开关；重新全局开启后，它才会重新出现。

实际生效关系可以理解为：

```text
LSPosed 已勾选目标应用
        ↓
软件作用域已启用该应用
        ↓
组件作用域已全局启用该组件
        ↓
该应用详情中也启用了该组件
        ↓
动态识别命中目标 View / Drawable
        ↓
应用当前配置的材质
```

任意一层关闭，对应效果都不会在该应用上生效。

## 六、推荐配置方法

第一次使用时，建议不要一口气把所有功能全部打开。可以先：

1. 在 LSPosed 中只勾选你准备测试的应用。
2. 在「组件作用域」先开启「分组卡片」和「独立卡片」。
3. 在「软件作用域」确认目标应用处于开启状态。
4. 进入目标应用观察卡片效果。
5. 再逐步开启弹窗、搜索框、悬浮操作底栏、顶栏按钮等组件。
6. 需要整页背景时，再配置「全局设置」壁纸并开启「全局壁纸」；如果仍有大色块遮挡，再尝试「布局清理」。

这样遇到异常时更容易判断是哪一类组件造成的。

## 七、beta11 的动态识别有什么不同

beta11 的卡片适配开始采用内容驱动的通用识别：除了已知资源 ID 的快速路径，还会结合视图尺寸、自有背景、卡片形状、表面透明度以及外层卡面关系判断独立卡片。

Drawable 识别也支持继续解析 selector、layer-list、inset、ripple 等复合结构，并允许具有明确卡片形状的半透明表面进入材质管线。对于首次布局时尚未测量完成的 View，模块还会在尺寸变化后补判。

因此，动态适配的目标是让更多同类界面元素无需逐页写死规则即可使用统一材质。不过自动识别仍然会主动避开品牌色、图片和功能性控件，以减少误接管。

## 八、常见问题

### 软件作用域显示“模块未激活”

检查 LSPosed 是否已启用 HyperBackground，并确认模块作用域中至少勾选了目标应用。必要时结束 HyperBG 和目标应用后重新打开。

### LSPosed 已经勾选应用，但软件作用域里没有

先确认 LSPosed service 正常工作，再重新进入该页面。系统组件即使没有桌面启动入口也可以出现在列表中；无法解析应用名称时会直接显示包名。

### 开了柔光玻璃但看起来像普通颜色或磨砂

柔光玻璃依赖系统原生材质、硬件加速和背景模糊条件。条件不满足时会回退到可用效果。

### 某个应用完全没有效果

依次检查：LSPosed 作用域 → 软件作用域整包开关 → 组件作用域全局开关 → 单应用组件开关。修改后重新进入目标页面；必要时结束目标应用进程。

### 全局壁纸打开后没有背景

先到「全局设置」配置一张背景图。「全局壁纸」只负责把已经配置好的全局背景扩展到允许的作用域应用。

### 背景已经出现，但页面还有大片白色/深色遮挡

尝试为该应用开启「布局清理」。如果遮挡来自真正的功能控件、图片或品牌色区域，模块可能会有意保留它。

### 某张卡片没有被识别

beta11 增加了独立卡片命中、半透明卡面、主题表面和 near-miss 原因等诊断日志。反馈适配问题时，建议同时提供：应用/页面名称、系统版本、目标界面截图以及相关 Hook 日志。

## 九、关于第三方/额外作用域

beta11 的材质路由可以扩展到 LSPosed 中实际勾选的其它应用。对于不在 HyperBackground 官方背景适配范围内的应用，模块会尽量限制在卡片、弹窗等动态材质能力，不直接启用整套系统设置背景、主题和文字颜色管线。

这能降低跨应用测试时对原界面的破坏，但动态识别仍属于测试能力。建议一次只增加少量作用域，确认稳定后再继续扩展。

---

遇到动态适配异常时，请优先说明**目标应用 + 页面 + 组件类型 + 当前材质模式**，这样比只描述“这里没生效”更容易定位。
